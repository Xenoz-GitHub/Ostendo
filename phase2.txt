Phase 2 — Portfolio Customization

Goal:
Turn the Phase 1 template system into a customizable website builder, without introducing the full Canva-like editor yet.

The student should be able to take a template and make it feel like their own website.

1. Customization Dashboard

After choosing a template, the student gets an Appearance / Customize area.

They can modify:

Colors
Typography
Spacing
Borders
Buttons
Section visibility
Layout variations
Navigation style
Profile presentation

The important principle:

Customize the design without needing to understand CSS.

2. Theme Customization

Students should be able to choose their own visual theme.

Colors

For example:

Primary
Secondary
Background
Surface
Text
Muted text
Border
Accent

The system should provide sensible defaults.

Instead of giving them hundreds of color controls, provide a controlled design system.

Example:

Primary       [ ● ]
Background    [ ● ]
Text          [ ● ]
Accent        [ ● ]
3. Preset Color Themes

Provide several professionally designed presets.

For example:

Default
Midnight
Paper
Forest
Ocean
Warm
Monochrome

But no random gradient themes.

The student can start with a preset and modify it.

4. Typography

Allow controlled typography customization.

Students can choose:

Heading font
Inter
Geist
Manrope
Plus Jakarta Sans
etc.
Body font

A smaller curated selection.

Then:

Heading size
Body size
Line height
Font weight

should be controlled by the design system.

Don't expose 100 typography settings.

5. Button Customization

Students can customize the appearance of buttons.

For example:

Style
○ Solid
○ Outline
○ Ghost
Shape
○ Square
○ Slightly rounded
○ Rounded
Size
○ Small
○ Medium
○ Large

The button's behavior remains controlled.

We are changing:

How it looks

not:

How it executes arbitrary code.

6. Navigation Customization

Allow students to choose from several navigation styles.

For example:

Standard
Crystal    About Projects Experience Contact
Centered
          Crystal

    About Projects Contact
Minimal
Crystal                         Menu

The underlying navigation remains functional.

7. Section Visibility

Students should be able to decide what appears on their website.

Example:

☑ About
☑ Projects
☑ Experience
☑ Education
☑ Skills
☐ Testimonials
☑ Contact

If they don't have experience yet, they can simply disable it.

This is especially important for first-year students who may have very little content.

8. Section Ordering

Allow basic reordering.

For example:

Current order:

Hero
About
Projects
Experience
Education
Skills
Contact

They can change it to:

Hero
About
Skills
Projects
Education
Contact

This is not yet the free-form drag-and-drop editor.

We're only allowing controlled section reordering.

Each major section can have predefined layouts.

For example, Projects:

The student chooses a layout rather than manually positioning everything.

11. Background Customization

Allow:

Solid background
Surface background
Light/dark theme
Subtle borders

Avoid letting users create visually chaotic pages.

The editor should guide users toward good design.

That's one of the biggest differences between this and a completely unrestricted website builder.

12. Live Preview

This becomes very important in Phase 2.

The student changes:

Primary color → Blue

and immediately sees the website update.

Conceptually:

┌────────────────────┬─────────────────────────┐
│                    │                         │
│ Customize          │       Preview           │
│                    │                         │
│ Colors             │   Crystal Santos        │
│ Typography         │                         │
│ Buttons            │   Computer Science     │
│ Layout             │   Student              │
│ Sections           │                         │
│                    │   [ Projects ]          │
│                    │                         │
└────────────────────┴─────────────────────────┘

No need to constantly save and refresh.

13. Desktop / Mobile Preview

Add a preview switcher:

[ Desktop ] [ Tablet ] [ Mobile ]

The student can verify their design at different sizes.

The actual public website must still be responsive automatically.

14. Save Changes

Students should be able to:

Save changes

and:

Publish changes

This creates an important distinction.

Editing

Changes are private.

Publishing

Changes become visible to visitors.

For example:

Current published version
        ↓
Student edits
        ↓
Draft
        ↓
Preview
        ↓
Publish
        ↓
New public version

This will become extremely useful later when we introduce the full visual editor.

15. Reset Customization

Provide:

Reset to template defaults

This should restore the original design settings without deleting the student's portfolio content.

For example:

Reset appearance?

This will restore the template's default colors, fonts, spacing, and layouts. Your portfolio content will not be deleted.

16. Design Presets

Allow students to save their customization as a preset.

For example:

My Theme

This becomes useful later when students have multiple pages.

Eventually:

My Theme
├── Colors
├── Typography
├── Buttons
├── Spacing
└── Components
17. Important Architecture Principle

Phase 2 should establish a separation between:

Content
Name
Bio
Projects
Education
Experience
Skills

and:

Presentation
Colors
Fonts
Spacing
Layouts
Section order
Visibility
Template

So:

Portfolio
│
├── Content
│
└── Design

This separation is critical.

Because Phase 3 will add the visual editor.

18. Preparing for the Canva-like Editor

We should design Phase 2 so that eventually we can move from:

Template
   ↓
Customization

to:

Template
   ↓
Visual Editor
   ↓
Sections
   ↓
Components
   ↓
Actions

The customization system shouldn't become a dead-end.

20. Vercel Plan

Still use Vercel for application hosting.

Development remains:

Local Next.js
      ↓
Local MySQL

Production eventually:

GitHub
   ↓
Vercel
   ↓
Next.js
   ↓
Hosted MySQL

The goal remains $0 while we're building and validating the product, using free tiers where available.

21. PWA

The dashboard should continue becoming a proper PWA.

The customization editor should work well on:

Desktop
Tablet

For the actual editing experience, desktop should be the primary target initially because visual website editing requires more screen space.

The public portfolio remains fully mobile responsive.

22. What Phase 2 Does NOT Include

Still no:

❌ Free-form canvas
❌ Arbitrary element positioning
❌ Custom HTML
❌ Custom JavaScript
❌ Custom CSS
❌ Advanced interactions
❌ Complex animations
❌ Plugin system
❌ Marketplace

Those belong to the visual editor phase.

Phase 2 Success Criteria

Phase 2 is complete when a student can:

Choose Template
      ↓
Customize Colors
      ↓
Change Typography
      ↓
Choose Layout
      ↓
Reorder Sections
      ↓
Hide Sections
      ↓
Customize Buttons
      ↓
Preview Desktop/Mobile
      ↓
Save Draft
      ↓
Publish

And two students using the same template can end up with noticeably different websites.
